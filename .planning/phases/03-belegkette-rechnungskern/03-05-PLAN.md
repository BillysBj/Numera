<objective>
Build the single most important transaction in v1: **finalize**. In one DB transaction it {validates §14 completeness, snapshots issuer + recipient onto the document as jsonb, computes + persists the BG-23 VAT breakdown via `VatCalculationService`/`RoundingPolicy`, assigns the invoice number race-safely via an atomic upsert-returning counter in the configured format, computes the due date + creates the open item, flips status to Finalized last, records the audit event} and — after commit — dispatches an `InvoiceFinalized` domain event through a tiny in-process publisher.

Purpose: INV-01 (§14 fields snapshotted), INV-02 (race-safe unique configured-format numbering), OPDN-01 (open item on finalize), and the ledger-readiness seam (RESEARCH.md Q8). LOCKED: numbering is `INSERT..ON CONFLICT..DO UPDATE..RETURNING` (Pattern 3, NO SEQUENCE / NO MAX+1); breakdown rows are inserted while status is still Draft and status flips LAST (Pattern 4 + Pitfall 1, via two SaveChanges in one transaction); a rolled-back finalize skipping a number is legal — do NOT build gap-backfill.

Output: NumberingService, the domain-event seam + publisher, the finalize endpoint + finalize validator, Program.cs DI for the publisher.
</objective>

  <files>src/modules/Numera.Modules.Sales/Numbering/NumberingService.cs</files>
  <action>
    `public sealed class NumberingService` taking `NumeraDbContext`. Method `Task<string> AssignAsync(DocumentType docType, int year, CancellationToken ct)` that MUST run inside the caller's finalize transaction:
    1. Atomically claim a number via a single statement (RESEARCH.md Pattern 3, verbatim intent):
       ```
       INSERT INTO number_sequences (id, tenant_id, doc_type, year, next_value)
       VALUES (@id, current_setting('app.current_tenant')::uuid, @docType, @year, 2)
       ON CONFLICT (tenant_id, doc_type, year)
       DO UPDATE SET next_value = number_sequences.next_value + 1
       RETURNING next_value - 1 AS assigned;
       ```
       Run via `db.Database.SqlQuery<long>($"...")` (interpolated → parameterized). Because it is one statement under the ON CONFLICT row lock, concurrent finalizations serialize per (tenant,doc_type,year) and cannot collide. NEVER a Postgres SEQUENCE, NEVER MAX()+1.
    2. Load the tenant's `document_number_formats` row for `docType` (if absent, use sane defaults: prefix by type e.g. "RE-"/"ST-"/"GS-", includeYear=true, padding=5). Render `{prefix}{year?"-":""}{assigned:0{padding}}` → e.g. "RE-2026-00001". `year` param = includeYear ? documentDate.Year : 0 (never-reset series use year 0).
    Return the rendered number. Do NOT open its own transaction/SaveChanges — it participates in the finalize transaction.
    Register in DI later (Program.cs task 3) as scoped, OR construct inline in the endpoint — prefer scoped DI.
  </action>
  <verify>`dotnet build` green; a unit or inline check that two sequential AssignAsync calls (same series) yield N and N+1; format renders "RE-2026-00001".</verify>
  <done>Numbering is atomic (ON CONFLICT upsert-returning), per (tenant,doc_type,year), and formatted per document_number_formats — no SEQUENCE/MAX+1.</done>
