- `SelectCandidates(openItems, configs, today)` — for each OP where `due_date < today AND status IN (Open, PartiallyPaid)`, compute `daysOverdue = today - due_date`; the next level = `current_dunning_level + 1`; the OP is a candidate ONLY when a config row for that level exists, `daysOverdue >= config.DaysAfterDue`, and `last_dunned_on != today` (idempotency — RESEARCH Pitfall 5/6). Fees/interest are Nebenforderungen — they NEVER modify `OpenItem.OpenAmount` (LOCKED anti-pattern).
