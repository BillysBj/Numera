<objective>
Build the outbound XRechnung pipeline and the two-stage KoSIT validation gate. A finalized invoice's numbered XRechnung (UBL+CII) is generated from the frozen snapshot (05-01), validated against KoSIT (05-02), and stored with its validation status in a new RLS-scoped `document_einvoice` table by a Hangfire job. The gate has two stages: a synchronous PRE-finalize dry-run that blocks finalize before a gapless number is burned, and a POST-finalize authoritative status that blocks the e-invoice send unless the stored XML was Accepted. Users can download the XRechnung as UBL or CII.

Purpose: Delivers EINV-01 (generate + download) and EINV-03 (validate before finalize, errors block the Versand, explained) — resolving RESEARCH Pitfall 1 (the "vor Finalisierung" vs. number-assignment conflict) with the two-stage design. This is the heaviest plan of the phase; it targets the upper end of the context budget. Depends on the mapper (05-01) and the validator (05-02).
Output: `EInvoiceArtifact` entity + migration + RLS, `EInvoiceService`, `GenerateEInvoiceJob`, `EnqueueEInvoiceOnFinalize`, `EInvoiceEndpoints`, the pre-finalize dry-run in finalize, deterministic integration tests, and a checked-in live-KoSIT conformance harness (Task 4) that proves the real generated XRechnung is Accepted by the real validator — closing RESEARCH Pitfall 2 (the fake-validator tests never could).
</objective>
