<task type="auto">
  <name>Task 2: IEInvoiceValidator + KoSitValidatorClient + KoSitReport parser (DE/EN findings)</name>
  <files>src/Numera.Api/Numera.Api.csproj, src/Numera.Api/Services/IEInvoiceValidator.cs, src/Numera.Api/Services/KoSitValidatorClient.cs, src/Numera.Api/Services/KoSitReport.cs, src/Numera.Api/Program.cs</files>
  <action>
Define `IEInvoiceValidator` with `Task<EInvoiceValidationResult> ValidateAsync(byte[] xml, CancellationToken ct)`. Define result records: `EInvoiceValidationResult(EInvoiceValidationStatus Status, IReadOnlyList<EInvoiceFinding> Findings, string? RawReport)` where `EInvoiceValidationStatus` = `Accepted | Rejected | Unavailable`; `EInvoiceFinding(string Severity, string? RuleId, string Message, string? ExplanationDe, string? ExplanationEn)`. These are the SEAM 05-03 (persistence/gate) and 05-05 (inbound) both consume.

`KoSitValidatorClient : IEInvoiceValidator` — a typed HttpClient (registered via `AddHttpClient<IEInvoiceValidator, KoSitValidatorClient>` bound to the options BaseUrl+Timeout):
- POST the XML as `application/xml` to the sidecar's validation path; read the XML report string.
- On success: `KoSitReport.Parse(report)` → status + findings.
- On `HttpRequestException`/`TaskCanceledException` (timeout)/connection failure: return `Status = Unavailable` with a clear message — NEVER map an outage to `Rejected` (RESEARCH Pitfall 6). Log it.

`KoSitReport.Parse(string reportXml)` (static, pure) using `System.Xml.Linq`:
- Read the report's computed acceptance (`accept`/`reject`) into `Accepted`/`Rejected`.
- Extract each finding: rule id, severity (error/warning/info), message. Errors block; warnings inform (group by severity).
- Enrich with a DE(authoritative)+EN explanation map for the common German-CIUS + EN-16931 rule ids (e.g. `BR-DE-15` Leitweg-ID/BT-10, `BR-DE-*` electronic address, `BR-CO-10/13/15` totals coherence). Fall back to the raw KoSIT message for unmapped rules (RESEARCH "verständlich erklärt"). Keep the map a private static dictionary — a data fill, extendable later.
Capture ONE real report from the running sidecar (Task 1) against a golden UBL from 05-01's output — but since 05-02 runs parallel to 05-01, if the mapper output is not yet available, hand-craft/obtain a representative KoSIT report XML to pin the parser XPaths to (RESEARCH Open Question 2). Register the typed client in Program.cs.
  </action>
  <verify>`dotnet build src/Numera.Api` → 0 warnings; the typed client is registered; a manual POST of a known-good XRechnung returns `Accepted`, a known-bad one returns `Rejected` with findings, and stopping the sidecar returns `Unavailable` (not Rejected).</verify>
  <done>IEInvoiceValidator posts to the sidecar and returns a structured Accepted/Rejected/Unavailable result with DE/EN-explained findings; outage is distinct from rejection; DI wired.</done>
</task>
