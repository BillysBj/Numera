<objective>
Ingest received e-invoices: a user uploads an XRechnung (UBL/CII XML) or a ZUGFeRD PDF; the system detects the format, extracts the embedded XML (PdfPig) when it is a PDF, parses it via `InvoiceDescriptor.Load` (the same ZUGFeRD-csharp library used outbound), validates it against KoSIT, matches the supplier by VAT id, and stores the immutable original bytes + a human-readable read-model in a new RLS-scoped `inbound_document` table. A bilingual frontend shows the inbound list and a human-readable detail.

Purpose: Delivers EINV-04 (upload, validate, human-readable display) and EINV-05 (matched to the supplier, filed as an Eingangsbeleg) — legally required to be able to RECEIVE since 2025-01-01. Depends on 05-03 (the `IEInvoiceValidator` seam is wired + registered, and ZUGFeRD-csharp is on the Sales module). Runs parallel to 05-04 (disjoint files: inbound + web + a migration vs. PDF generation; 05-05 owns the sole wave-3 migration + the Program.cs edit).
Output: `InboundDocument` entity + migration + RLS, `InboundParser` + `SupplierMatcher`, `InboundEInvoiceService`, upload/list/detail endpoints, PdfPig on the Sales module, and the inbound frontend (DE authoritative).
</objective>
