`KeycloakBffExtensions.AddKeycloakBff(this IServiceCollection, IConfiguration)`:
- `AddAuthentication` with default scheme = Cookie, default challenge = OpenIdConnect.
- `.AddCookie()` — HttpOnly, SameSite=Lax, secure, sliding expiration → this is the persistent SPA session.
- `.AddOpenIdConnect()` — Authority `http://localhost:8080/realms/numera` (from config), ClientId `numera-bff`, ClientSecret from config, `ResponseType=code`, `UsePkce=true`, `SaveTokens=true` (tokens stay server-side), add scope `organization`, `GetClaimsFromUserInfoEndpoint=true`. Map the org id claim through.
Follow RESEARCH.md Pattern 5 sketch.

Register it scoped in DI (see below).

`RegistrationService` — given {email, password, companyName}: use the Keycloak Admin REST API (client-credentials of a small admin client, or the bootstrap admin for dev) to (a) create a user, (b) create an Organization for the company, (c) add the user as a member. Then mirror into the app DB: insert a `tenants` row using the Keycloak Organization id as `Tenant.Id` (default Plan = S), and a `membership` row (Role = Owner, UserId = Keycloak sub). Write an `AuditEvent` "tenant.created" in the same transaction. Enqueue a Hangfire welcome-email job (the trivial job proving enqueue-after-commit + tenant context — the job just logs/records; no SMTP yet). Reference RESEARCH Open Question 3: Keycloak is the IAM source of truth, the app DB mirrors membership so RLS/joins work without live IAM calls.

`TenantResolutionMiddleware` — runs after authentication: read the `organization` claim from the authenticated principal, look up (or trust) the matching `tenants.id`, and call `ICurrentTenant.SetTenant(tenantId)` so the connection interceptor sets `app.current_tenant` and RLS filters. For unauthenticated/no-org requests (e.g. registration, health), skip. Register it in the Api pipeline after `UseAuthentication`.

`AuthEndpoints` — minimal endpoints: `POST /api/auth/register` (calls RegistrationService), `GET /api/auth/login` (OIDC challenge), `POST /api/auth/logout` (cookie + OIDC sign-out). Login persistence is delivered by the cookie from Task 1.
  </action>
