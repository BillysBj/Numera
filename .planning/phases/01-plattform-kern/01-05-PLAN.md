<objective>
Build the server-side tier entitlement layer: a `Plan` (S/M/L/XL) → `Capability` map as the single source of truth, an `IEntitlementService` that resolves the current tenant's plan (from the `tenants.plan` column) to a capability set, and a `Microsoft.FeatureManagement` custom feature filter so endpoints can be gated with an attribute whose check is `auth ∧ tenant ∧ entitlement`. Frontend visibility (plan 01-06/07) is cosmetic; the server guard is authoritative. No payment processing.

Purpose: Success criterion 6 requires tier gates that visibly enable/disable features per tenant. Modeling as entitlements means a future Stripe webhook flips one DB column.
Output: Plan/Capability model, entitlement service, feature filter, tests.
</objective>
