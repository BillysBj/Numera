Add an EF migration `AuditEvents`. After creating the `audit_events` table, emit raw SQL:
```
-- RLS (tenant isolation) like other tenant tables
ALTER TABLE audit_events ENABLE ROW LEVEL SECURITY;
ALTER TABLE audit_events FORCE ROW LEVEL SECURITY;
CREATE POLICY tenant_isolation ON audit_events
  USING (tenant_id = current_setting('app.current_tenant')::uuid)
  WITH CHECK (tenant_id = current_setting('app.current_tenant')::uuid);

-- Append-only: app role may INSERT/SELECT only
REVOKE UPDATE, DELETE ON audit_events FROM numera_app;
GRANT INSERT, SELECT ON audit_events TO numera_app;

-- Belt-and-braces trigger (blocks even a mis-granted UPDATE/DELETE)
CREATE FUNCTION audit_no_mutate() RETURNS trigger LANGUAGE plpgsql AS $$
BEGIN RAISE EXCEPTION 'audit_events is append-only'; END; $$;
CREATE TRIGGER audit_immutable BEFORE UPDATE OR DELETE ON audit_events
  FOR EACH ROW EXECUTE FUNCTION audit_no_mutate();
```
Add a tenant_id-leading composite index (e.g. `(tenant_id, occurred_at)`) for query performance. Provide a `Down` that drops the trigger/function/policy and restores grants.

IF EXISTS (SELECT FROM pg_roles WHERE rolname='numera_app') ... $$` block so the trigger (the real enforcement) still applies. The trigger must always be created.
