  <files>src/Numera.Api/Services/TenantExportService.cs</files>
  <action>
Create a scoped `TenantExportService` (ctor injects `NumeraDbContext`). Add one method:
`Task WriteArchiveAsync(Stream output, CancellationToken ct)` that writes a `System.IO.Compression.ZipArchive(output, ZipArchiveMode.Create, leaveOpen: true)` entry-by-entry so peak memory stays bounded — NEVER materialize the whole archive as a byte[].

Archive layout (per 09-RESEARCH.md §1):
- `manifest.json` — export UTC timestamp, tenant id + name, a schema version constant, and a per-table row count map.
- `README.txt` — plain-language DSGVO Art. 20 note. WORDING (locked): use "GoBD-konform"/"DSGVO-konform" phrasing ONLY; MUST NOT contain "zertifiziert"/"certified".
- `data/{table}.json` — one file per RLS-scoped table, an array of rows, via `JsonSerializer.SerializeAsync(entryStream, rows, opts, ct)` over an `AsNoTracking()` `IQueryable`.
- `files/...` — the real binary blobs written straight into entries (NEVER base64 into JSON).

Include EVERY RLS-scoped table enumerated in 09-RESEARCH.md §1 (verify the list against the DbContext sets / `NumeraDbContextModelSnapshot`): Platform (tenants own row, membership, audit_events); Catalog (catalog_items); Crm (partners incl. owned company/address value objects, partner_contacts, partner_notes, partner_activities, partner_tasks, customer_files); Ledger (accounts, journal_entries, postings); Sales (company_profile, document_number_formats, number_sequences, sales_documents, sales_document_lines, sales_document_tax_breakdown, sales_document_prepayment, open_items, payment, payment_allocation, dunning_level_config, dunning_notice, recurring_invoice_templates, recurring_invoice_template_lines, document_render, document_email, document_einvoice, inbound_document).

Blob entries (extract the bytea column, one file per row):
- document_render → `files/renders/{documentNumber-or-id}.pdf`
- document_einvoice → `files/einvoice/{documentNumber-or-id}-{format}.xml`
- inbound_document → `files/inbound/{id}-{originalName}`
- customer_files → `files/customer-files/{partnerId}/{fileName}`
- company_profile → `files/company/logo.{ext}` (only if a logo is present)

For the JSON of blob-bearing tables, serialize metadata only (omit the raw byte[] property) to avoid duplicating bytes — the bytes live under `files/`. Do NOT open a write transaction; use `AsNoTracking()` throughout. RLS is already active on the request connection (the tenant middleware set `app.current_tenant`), so every query is tenant-scoped automatically — do not add manual `WHERE tenant_id=` filters.
