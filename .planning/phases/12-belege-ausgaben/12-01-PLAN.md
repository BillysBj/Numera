<objective>
Extend the Phase-10 expense posting rule so BELEG-05 can book (a) **0% / steuerfrei** supplier expenses and (b) **multi-rate** receipts/e-invoices. Today `ExpensePostingSource`/`ExpensePostingInput` are SINGLE-RATE only and `SkrMapping.ExpenseMapping` throws for any rate ≠ 19/7 (SkrMapping.cs:91-92) — both block real receipts.

The multi-rate change **mirrors the existing `InvoicePostingSource` precedent** exactly: that source already takes `IReadOnlyList<InvoicePostingBreakdown>` and loops INSIDE one `BuildPostings()` to produce a single balanced leg-set for ONE `PostAsync` / ONE `JournalEntry` (because `PostingEngine.PostAsync` throws if the header already has postings — PostingEngine.cs:33-36, so it can only be called once per header). We do the same for expenses so a multi-rate e-invoice books N legs into ONE entry that the single `Receipt.JournalEntryId` can link.

Purpose: unblock the confirm→book path (12-05) for zero-rated AND multi-rate expenses without a new posting engine.
Output: `ExpensePostingSource` accepts a breakdown list (single-rate path preserved) and 0% rows; `PostingEngine.PostAsync` is still called exactly once per booking.
</objective>
