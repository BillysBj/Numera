`PollBelegMailboxJob.cs` — a Hangfire recurring job. Because it fans out across tenants, it does NOT `SetTenant` at the top; instead, for EACH fetched message it resolves the recipient → tenant, THEN opens a scope + `SetTenant(tenantId)` (the established per-message pattern). Steps:
1. Connect a MailKit `ImapClient` to the configured mailbox (SSL), open INBOX, fetch UNSEEN messages (envelope + Message-Id + recipients + attachments).
2. For each message: parse the delivered-to / To local-part `belege-{token}@{domain}`; look up `TenantBelegeMailbox.AddressToken` → `TenantId`. Unresolved/ambiguous (0 tenants) → log + move to a quarantine folder / mark seen, DO NOT ingest (PITFALLS 3 — never route one mail to >1 tenant).
3. Open a DI scope, `SetTenant(tenantId)`. Idempotency: if `processed_belege_mail` already has this `(tenant, Message-Id)`, skip (never double-create). Otherwise iterate PDF/image/XML attachments and call `ReceiptIngestService.IngestAsync(bytes, fileName, contentType, ReceiptSource.Email, uploadedByUserId: null, ct)` — which scans (D4), archives WORM, creates the Receipt, dedups on content hash, and enqueues extraction (Tier B) exactly like an upload. (An e-invoice XML/ZUGFeRD attachment still flows through the ingest service; routing it to the Tier-A `InboundEInvoiceService` path is a planner-discretion enhancement — the ingest service already scans+archives.)
4. Record the `Message-Id` in `processed_belege_mail`, mark the message seen/move it. `[AutomaticRetry]` for transient IMAP faults; safe to re-run any window.
