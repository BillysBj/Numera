<objective>
Build the shared report-time **recognition read model** that both Phase-11 reports (USt-VA and EÜR) sit on. This is the crux of the phase and its highest-risk correctness surface.

There are two recognition paths, both RLS-scoped raw-SQL reads mirroring `LedgerEndpoints`:
- **Soll (accrual):** sum tax-bearing postings by `journal_entries.entry_date` in the period, grouped by `Account.UstvaKennziffer` + `Posting.TaxCategory` + `Posting.TaxRatePercent` + `Posting.Direction`. Uses the frozen Phase-10 posting metadata directly (LOCKED D1: "driven off account + Steuerschlüssel, never re-derived").
- **Ist / cash-basis:** payment-date attribution. Phase-10 payment postings carry NO tax metadata (verified: `PaymentPostingSource` books only Bank↔Forderung). So for each `Payment` whose `ValueDate` falls in the period, attribute its allocations pro-rata over the invoice's FROZEN `SalesDocumentTaxBreakdown` and recognize the net + VAT at the payment date. Reversals net out.

Purpose: keeps the Phase-10 ledger FROZEN (D1) — all Ist/cash re-timing is a report-time read over existing immutable data, no engine/migration/posting change.
Output: a `RecognitionReader` service + typed row models, proven on real Postgres.
</objective>

Recognition rule (LOCKED D1/D2 — re-timing, NOT re-derivation):
- Source rows: every `payment p` with `p.value_date BETWEEN {from} AND {to}`, joined `payment_allocation pa ON pa.payment_id = p.id`, `open_items oi ON oi.id = pa.open_item_id`, `sales_documents sd ON sd.id = oi.document_id`, `sales_document_tax_breakdown b ON b.document_id = sd.id`.
- Pro-rata factor per allocation = `pa.allocated_amount / NULLIF(sd.total_gross, 0)` (guard divide-by-zero).
- For each breakdown bucket recognize: `NetAmount = factor * b.taxable_base`, `VatAmount = factor * b.tax_amount`, carrying `b.tax_category`, `b.vat_rate_percent`, and `RecognizedOn = p.value_date`.
- Reversals: because `pa.allocated_amount` is NEGATIVE for a reversal allocation and reversal payments have negative `p.amount` with `value_date` in their own period, the pro-rata factor is negative and nets the recognition back out — do NOT filter reversals; add a comment. (Verify this holds in Task 3.)

- RLS auto-applies; no manual tenant filter.

Add an XML-doc note that this same cash read powers BOTH Ist-USt-VA (Plan 02) and EÜR cash-basis income (Plan 03), so neither double-counts the invoice+payment postings.
